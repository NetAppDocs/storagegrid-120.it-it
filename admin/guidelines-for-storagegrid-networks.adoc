[[grid-network]]
=== ${post_edited_translations.segment}

Obbligatorio. La rete Grid viene utilizzata per tutto il traffico interno di StorageGRID. Fornisce connettività tra tutti i nodi della grid, attraverso tutti i siti e le sottoreti.



[[admin-network]]
=== Rete di amministrazione

Opzionale. La Admin Network viene in genere utilizzata per l'amministrazione e la manutenzione del sistema. Può essere utilizzata anche per l'accesso al protocollo client. La Admin Network è in genere una rete privata e non deve essere instradabile tra i siti.



[[client-network]]
=== ${post_edited_translations.segment}

Opzionale. La rete client è una rete aperta, in genere utilizzata per fornire accesso alle applicazioni client S3, così la rete Grid può essere isolata e protetta. La rete client può comunicare con qualsiasi sottorete raggiungibile tramite il gateway locale.



[[guidelines]]
== Linee guida

* Ogni nodo StorageGRID richiede un'interfaccia di rete dedicata, un indirizzo IP, una subnet mask e un gateway per ciascuna rete a cui è assegnato.
* Un nodo della griglia non può avere più di un'interfaccia su una rete.
* È supportato un singolo gateway per rete e per nodo della griglia, e deve trovarsi sulla stessa sottorete del nodo. Puoi implementare un routing più complesso nel gateway, se necessario.
* Su ciascun nodo, ogni rete è associata a una specifica interfaccia di rete.
+
[cols="1a,1a"]
|===
| Rete | Nome dell'interfaccia 


 a| 
Griglia
 a| 
eth0



 a| 
Amministratore (facoltativo)
 a| 
eth1



 a| 
Cliente (facoltativo)
 a| 
eth2

|===
* Se il nodo è connesso a un'appliance StorageGRID, vengono utilizzate porte specifiche per ciascuna rete. Per dettagli, consulta le istruzioni di installazione della tua appliance.
* Il percorso predefinito viene generato automaticamente per ogni nodo. Se eth2 è abilitato, 0.0.0.0/0 utilizza la Client Network su eth2. Se eth2 non è abilitato, 0.0.0.0/0 utilizza la Grid Network su eth0.
* La rete client non diventa operativa finché il nodo della griglia non si è unito alla griglia

[[optional-interfaces]]
== Interfacce opzionali

Opzionalmente, puoi aggiungere interfacce extra a un nodo. Ad esempio, potresti voler aggiungere un'interfaccia trunk a un nodo Admin o Gateway, in modo da poter utilizzare link:../admin/configure-vlan-interfaces.html["Interfacce VLAN"] per segregare il traffico appartenente a diverse applicazioni o tenant. Oppure, potresti voler aggiungere un'interfaccia di accesso da utilizzare in un link:../admin/configure-high-availability-group.html["gruppo ad alta disponibilità (HA)"].

Per aggiungere interfacce trunk o di accesso, vedi quanto segue:

* *VMware (dopo l'installazione del nodo)*: link:../maintain/vmware-adding-trunk-or-access-interfaces-to-node.html["VMware: Aggiungi interfacce trunk o di accesso a un nodo"]
+
** *Linux (prima dell'installazione del nodo)*: link:../swnodes/creating-node-configuration-files.html["Crea i file di configurazione del nodo"]
** *Linux (dopo l'installazione del nodo)*: link:../maintain/linux-adding-trunk-or-access-interfaces-to-node.html["${post_edited_translations.segment}"]





NOTE: "Linux" si riferisce a un'installazione di RHEL, Ubuntu o Debian. Per un elenco delle versioni supportate, vedi  https://imt.netapp.com/matrix/#welcome["NetApp Interoperability Matrix Tool (IMT)"^].
